## Decision proposed for review

Meeting mode should be a passive, in-memory feed view, with a separate lifecycle identity and **no Glass database session**. A Fireflies `transcriptId` or feed `instanceId` must never be passed to a session repository as a substitute database ID. The server remains responsible for capture, transcript retention and automatic suggestions.

Simply omitting `initializeNewSession()` is insufficient. Local transcript callbacks still invoke SummaryService; resetting SummaryService does not clear its session ID or invalidate asynchronous work; Ask independently creates a session and captures a screenshot. These findings require explicit mode guards and cancellation boundaries.

For Step 3b I recommend disabling Ask while Meeting is selected, including its shortcut and main-process entry points. This is a **proposal requiring this checkpoint's review**, not an implemented restriction. It keeps the authorized overlay passive and satisfies the strict no-capture/no-database-session rule. The explanation can read “Ask is available in Local mode.” Switching back to Local restores existing Ask behavior. A useful alternative is text-only, ephemeral Ask with no screenshots or persistence, but that needs a separately specified context/retention policy and additional Ask work. Leaving Ask unchanged would create or reuse a database session during meeting mode and therefore does not meet the strict rule.

The absence of a meeting session does not imply disabling the application's database, default user, saved history, or account maintenance. Those existing facilities can continue operating on previously persisted records. The meeting lifecycle itself must not call them to create, touch, promote, end or persist a meeting record.

## Proposed source selection and eligibility

1. Add an explicit **Local / Meeting** selector in MainHeader. Main owns the selected source and publishes authoritative source/lifecycle state to Header and Listen. Keep the selector disabled while starting, active or stopping: Stop first, then change source. Keep selection in main-process memory, outside provider settings.
